# /week <тема1, тема2, …> — неделя роликов

**Зачем так:** в одной длинной сессии качество рисовки падает (контекст забит — миры беднеют, Том мельчает; 013–016 просели, 03.11.2026; в ТОМ-ТУР было то же). Поэтому главный чат — **продюсер**: планирует, проверяет и сдаёт, а каждый ролик целиком делает **отдельный агент со свежим контекстом** по скилу `episode`. Продюсер миры сам не пишет и большие файлы не читает.

## 0. Старт (продюсер)
1. Прочитать `STATUS.md`, `tail -30 docs/dishes.md` (что было — не повторять), `docs/week.md` (если есть незаконченная неделя — продолжить её, а не начинать новую).
2. `git checkout main && git pull origin main` (если сессия задала свою ветку — работать в ней, сдавать fast-forward в main).
3. Номера: следующий после последнего в `docs/dishes.md`, по порядку тем владельца.

## 1. План недели — `docs/week.md` (без одобрения владельца, ~15 мин)
Для каждой темы — короткий быстрый поиск (2–3 запроса), чтобы найти **крючок** — самый странный реальный факт или легенду. Таблица, по строке на ролик, **все 7 строк разные** (меню — `docs/episode-formula.md`):
| № | блюдо | тип хука (шок-цифра / разоблачение легенды / загадка имени / суд-скандал / парадокс / «а вы знали» / спор стран…) | хук-фраза | развязка ★ | Том-малыш (что делает внутри блюда) | палитра | финальная фраза | статус |
Правила разнообразия: соседние ролики — разный тип хука и палитра; Том-малыш каждый раз с новым действием; финальные фразы не повторяются; переходы — каждый ролик свой набор (учёт — `docs/dishes.md`). Коммит `docs/week.md`. Владельцу — 1 строка «План недели готов, начинаю с …» (план можно прислать файлом).

## 2. Ролик за роликом (по одному, строго по очереди)
Для каждой строки плана — **новый агент** (Agent, `subagent_type: general-purpose`, **без** `model` — та же модель, что у продюсера; `run_in_background: true` — продюсер заканчивает ход и ждёт уведомления, не опрашивает). Бриф (≤ 15 строк):
```
Ты делаешь выпуск «ТОМ НА ВКУС» <NNN-блюдо> («<Блюдо>») от и до в репозитории /home/user/tom-food.
Загрузи скил `episode` и иди по нему полностью: facts → scene → sound → deliver. Одобрения не ждать (очередь владельца).
План ролика (из docs/week.md): хук «…», тип хука …, развязка …, Том-малыш …, палитра …, финал «…».
Обязательно: визуал не ниже эталона (Read docs/ref/etalon_sheet.jpg и 1–2 мира 002-olivier/003-shuba/002-nuggets перед мирами);
Том крупный, по пояс; камера близко; плашка ПОДПИШИСЬ; саунд-дизайн по скилу `sound`; перед рендером `python3 tools/qa.py <эп>` — без ⚠.
Факты — только проверенные, 2+ источника (docs/sources/<эп>.md); ударения — по tools/stress.md.
Не отправляй файлы владельцу и не делай общий файл выкладки — это делает продюсер.
Рендер (~15 мин): Bash run_in_background, ждать через Monitor (until-loop: нет процесса render.sh и есть build/<эп>/chat.mp4), не sleep.
Коммить и пушь после каждого большого этапа (сессию могут перезапустить). В конце: коммит + push + fast-forward в main. Верни: пути chat.mp4 / cover.png, вывод qa.py и final.sh, 3 строки о слабых местах честно.
```
После агента продюсер:
1. `python3 tools/qa.py <эп>` — всё ✓. `bash tools/final.sh <эп>` — LUFS −14 ± 0,5, пик ≤ −1, ПОДПИШИСЬ вкл.
2. Read `build/<эп>/final_sheet.jpg` **рядом** с `docs/ref/etalon_sheet.jpg`: Том крупный и по пояс в большинстве кадров, миры плотные (4–5 планов, люди, утварь, свет/дымка), блюдо-герой аппетитное, текст не перекрывает лицо, ничего важного вне безопасной зоны.
3. Если хуже эталона или есть ⚠ — SendMessage тому же агенту с конкретным списком правок (кадр → что не так → как исправить) и повторный рендер. Не принимать «почти».
4. Владельцу: SendUserFile `chat.mp4` + `cover.png` (`status: proactive`) + 2 строки (хук, развязка; слабое место, если есть). **Без файла выкладки.**
5. В `docs/week.md` — статус строки «готово», коммит + push.

## 3. Конец недели
`python3 tools/publish_week.py <ДД.ММ.ГГГГ первого дня выкладки> <эп1> … <эпN>` → `docs/publish-all.md` (по дню на ролик, ~7:45–8:00) → коммит, push, ff в main → **один раз** SendUserFile `docs/publish-all.md` + 3 строки итога. `STATUS.md` — что сделано и что дальше.

## Если сессию перезапустили / «продолжай неделю»
`docs/week.md` — источник правды: найти первую строку не «готово»; если агент не дошёл до рендера — проверить `git log`, `episodes/<эп>/` и запустить нового агента с брифом «продолжи выпуск с этапа …». Рендер уже был — только проверка и сдача.
